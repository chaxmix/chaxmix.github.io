Where it started

The platform grew for over a decade without a designer, and every module grew its own look: a blue form builder, a red action plan, a purple rate table and a dark borrower portal. Buttons, tables and tabs were rebuilt from scratch on almost every screen.

Screens from the legacy platform. All data is test data.

Foundations

Principle 01

Components never touch a raw color

Every fill, text and border is a semantic token that points to a primitive in each mode. Switching to dark mode swaps the pointers, not the components.

Principle 02

One type scale, one rhythm

DM Sans carries the product and Fields handles display moments. Every style sits on a 150% line height, so text from any part of the platform stacks cleanly.

Principle 03

Radius by role, not by taste

Corners say what an element is. Inputs use md, buttons use lg, and cards use xl, so nested elements always step down as they go in.

Buttons: 280 variants, one decision

The legacy product had dozens of one-off buttons: different heights, radii and casing on almost every page. The system version covers 4 sizes, 7 styles and 5 states. The hard part wasn't drawing them. It was deciding which choices an engineer should never have to make.

What I tried first

A separate component for every combination. It was easy to read in Figma, but impossible to keep in sync with code. I collapsed it into one Button with three properties (size, style, state), so the Figma component and the coded one share one API.

The rule that came out of it

One brand button per view

Every page has a single primary action. Everything else steps down to Neutral, Tonal or Ghost, which is why the after screen reads at a glance.

Building it with engineering

A system nobody adopts is just a Figma file. I worked directly with our frontend developer so every component landed in the codebase as it was designed.

What I learned

The ask is rarely the need. "Make it prettier" would have produced nicer screens on the same tangled base. Building the system first was slower to show, but every screen since has been faster and more consistent.

Next time I'd bring engineering leads in even earlier, so adoption starts with the first component instead of after the foundation.

The best compliment so far: nobody on the team talks about the system anymore. They just build with it.
